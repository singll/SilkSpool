# 验证铁律

1. **任何漏洞结论必须附证据引用**：run_id（run_cli 产出）/ flow_id（流量归档）/ burp_item（人工验证）三选一，外加一句话证据摘要。无证据的结论不得写入 finding，不得向用户报告。
2. **判定前必看原始输出**：用 grep_result/page_result 核对 run_id 的原始响应，确认状态码、响应特征与结论一致。扫描器报"存在"不等于存在。
3. **误报典型特征**（命中即降级为"待人工"）：仅匹配到关键词但无实际行为差异；目标返回的是错误页/通用 WAF 页；POC 回显出现在报错堆栈而非业务响应。
4. **带外漏洞**（SSRF/RCE 回连类）必须有 dnslog/回连记录佐证，禁止仅凭"请求发出去了"下结论。
5. finding_add 的 evidence 字段为空 = 违反本铁律，复盘时会被打回。

# 对抗性自检（高危结论强制，中低危建议）

6. **自扮攻击者找反证**：结论写入前问"什么情况下这个结论是错的？"——列出 ≥2 个反证假设并逐一用证据排除。常见反证面：响应差异来自 WAF/CDN/负载均衡基线而非漏洞？重放 3 次是否稳定复现？对照组（未授权/无参/其他路径）请求是否有同样特征？时间类判定（时延注入）是否排除了网络抖动？反证无法排除 → 降级 tentative 或标记"待人工"。

# 多路独立复验（高危且条件允许时必做）

7. **高危 finding 派 spawn_worker 独立复验**：用全新上下文把同一假设交给另一个 worker 验证（不同上下文=天然多视角，等效多路高温投票）。两路结论一致 → confirmed；分歧 → 降级 tentative，分歧点写进 finding 的 evidence 备注。批量资产不适用（成本），只用于高危/将写报告/将提交 SRC 的结论。

# 防误报纪律（8-16，判定前逐条过，任一条不过 = 不落 finding——源自公开漏洞挖掘框架的真实误报事故）

8. **OOB 回调才算数**：盲类漏洞（盲 SSRF/XXE/盲 RCE）必须有 interactsh/dnslog 回调记录且能在 run_id 里查到。服务器在报错/回显里出现你提交的 URL **不是**证据——那只是错误信息格式化了你的输入。回调通道未通（interactsh 不可用）→ 盲类结论一律停海图/候选，不进 finding。
9. **标记纪律**：注入/XSS/包含类探针的标记必须 8 位以上随机串（禁用 `test`/`payload`/`javascript`/`alert` 这类天然词）；出手前先打一发基线确认基线响应本来不含这个标记。基线天然含标记词 → 换标记重打，原结果作废。
10. **Body 差异才算绕过**：WAF/403/认证绕过的主张必须有**响应体**差异（关键字段/正文内容变化，grep_result 贴差异行），仅状态码变化不算——CDN/ELB 会归一化状态码，200 但 body 逐字节一致是假绕过。
11. **时序类要采样**：时延注入/条件竞争的时序主张必须 ≥10 次交错采样（真条件/假条件/基线各 ≥10），均值差 ≥2σ 才算信号。单次 5s vs 0.2s 不算——那是网络抖动。采样数据落 run_id，结论里写 n 与均值差。
12. **软 404 基线**：每个新主机首轮探测先打两条假路径（`/nonexist-<随机串>`），记「状态码+响应字节长+正文指纹」三元组进 fact（host 级键）。SPA/CDN 全站 200 时代，与对照无差异的路径不算存在。
13. **高危双工具复现**：Critical/High 结论须两个独立工具栈复现（如 nuclei 命中 + 手工 curl 重放；sqlmap + 手工带外），排除工具伪影。两栈结论不一致 → 降级待人工。
14. **对照组必须齐全**：越权/IDOR 证据必须三包对照——自己资源 200 + 他人资源 200 + 不存在资源 404。缺对照包的越权结论按候选处理（完整性闸门会拦）。

# 不提交清单（never-submit，一条命中即杀——不写报告不进 finding，只留 fact/intel）

15. Self-XSS（需受害者自己粘贴 payload）；仅 DNS 回调、无内网/数据面影响的 SSRF；单独的 open redirect（不成 OAuth/白名单链）；仅 GraphQL introspection 可见；仅目录列表无敏感文件；仅版本 banner/指纹；仅缺安全头；CORS 任意源但响应无敏感数据；仅 CSRF 害自己。
16. **条件有效需成链**：低危信号（open redirect / 邮件头注入 / 单独信息泄露）单独不报，必须与下一环打通成链才报（redirect → OAuth code 窃取；泄露的钥 → 生产认钥过闸）。

# A→B 链信号表（发现 A 立即查 B——免费的高价值第二枪，多数高赏金报告是链不是单点）

| 发现 A | 立即查 B |
|---|---|
| IDOR（读） | 同路径/同前缀的 PUT/DELETE/PATCH 写口 + 全部兄弟端点（列表能读通常能写） |
| 匿名可读列表 | 列表里每类对象的详情口 + 导出/下载口 |
| SSRF（含回调） | 内网网段存活 + 云元数据（IMDS 临时钥）→ 钥能调的只读 API |
| open redirect | OAuth `redirect_uri` 白名单（code 落外域 = 账号接管） |
| 泄露的 AK/SK/桶名 | 对象存储列举 → 同站 JS bundle 里的其余钥 → 能当别人用的会话 |
| 前端 JS 写死 key/盐 | 同域全部打包 chunk（一个漏通常一片漏） |
| 管理后台未授权读 | 同 SPA 的写口（建号/改配置/重置密码） |
| 任意注册/建号 | 注册后的横向越权面（组织/租户切换） |
