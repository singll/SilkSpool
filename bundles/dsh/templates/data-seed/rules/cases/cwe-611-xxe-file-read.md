# 案例：XML 导入功能的解析器没禁外部实体、读任意服务器文件（高危）

> 来源: https://nvd.nist.gov/vuln/detail/CVE-2011-4107 · CWE: 611 · 首发年份: 2011
> 关联: rules/techniques/xxe-test.md · VC 卡: 无

## 模式（什么形状的目标会有这洞）
功能吃 XML：导入/上传、SOAP 接口、文档预览、站点地图提交。解析器默认支持 DTD 与外部实体，代码没显式禁用。判例形态：管理工具的"XML 导入"插件用 simplexml 系函数直接解析用户提交的 XML，登录用户读走服务器任意文件。

## 打法（案例里实际打通的路径）
上传一个带外部实体声明的 XML，实体指向本地敏感文件路径，看回显是否带出文件内容。不回显就转外带：实体指向你控制的域，解析器替你发请求（DNS/HTTP 出网即是证据），再用参数实体把文件内容拼进外带 URL 分批带出。探测顺序、回显与外带的对照手法见 xxe-test 模块。

## 出什么算成
读到服务器上非公开文件的内容（回显或外带任一），或证明 SSRF（内网/云元数据经实体被访问）。

## 假点（什么样不算）
解析器禁了 DTD/外部实体（报"实体未定义"或直接拒绝）；上传口只认 xls/docx 等包装格式且内层不解析 XML；只能触发出网但读不到任何文件——如实写成 XXE→SSRF，不硬写文件读取。

## 为什么值钱（severity 依据）
文件读取可摸配置与密钥，外带即 SSRF 跳板（可接云元数据链）；管理面板类产品影响整个部署实例，高危起步。
