# 案例：个人页后面加个 .css 让 CDN 把隐私正文缓存下来（高危）

> 来源: https://omergil.blogspot.com/2017/02/web-cache-deception-attack.html · CWE: 525 · 首发年份: 2017
> 关联: rules/techniques/cache-poisoning-test.md · VC 卡: 无

## 模式（什么形状的目标会有这洞）
登录后才有内容的页面（账户/资料/账单）与静态资源共用一个域名，中间 CDN 的缓存规则按"URL 像不像静态文件"决定存不存——看扩展名不看 Cache-Control。判例在一家支付平台的个人资料页上打通。

## 打法（案例里实际打通的路径）
先登录，访问自己的个人页确认 URL 形状。在同一路径后追加伪静态后缀（.css/.js 等变体见 cache-poisoning-test 模块），再打一次：第一次 MISS、第二次 HIT，或未登录也能拿到，说明 CDN 把它当静态资源收了。然后诱导在线受害者点开你构造的带后缀链接，等它进缓存，最后未登录 GET 同一 URL，把对方的账户正文读走。

## 出什么算成
未登录（或换号）从缓存里拿到**他人**登录态页面的正文。

## 假点（什么样不算）
响应带 no-store/private 且 CDN 遵守；后缀变体只回 404 或登录跳转；需要受害者先点链接但你拿到的只有自己的缓存——没拿到他人数据不算成。

## 为什么值钱（severity 依据）
把"需要会话的隐私页"变成"公开 URL 一段时间内人人可读"，判例直接命中支付平台账户页，按大规模隐私泄露收高危。
