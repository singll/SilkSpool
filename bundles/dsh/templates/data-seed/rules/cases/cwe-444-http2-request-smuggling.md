# 案例：HTTP/2 降级到 HTTP/1.1 时的协议翻译走私（高危）

> 来源: https://portswigger.net/research/http2 · CWE: 444 · 首发年份: 2021
> 关联: rules/techniques/http2-attacks-test.md · VC 卡: 无

## 模式（什么形状的目标会有这洞）
入口说 HTTP/2、后端只说 HTTP/1.1，中间层把 H2 请求"翻译"回 1.1 时不过滤 H2 里合法但 1.1 里致命的语法：声明的 content-length 与实际 data 帧长度不符、伪首部映射出的 header 带非法字符等。入口信号：响应或 ALPN 显示前端支持 h2，后端是老 1.1 服务。

## 打法（案例里实际打通的路径）
先确认前后端协议版本组合。在 H2 请求里造 1.1 语义下的矛盾体：content-length 与 data 不一致（H2.CL），或构造 1.1 会按 Transfer-Encoding 解析的首部（H2.TE）。翻译层照单全收就造成后端队列错位，后续同连接请求被你走私的内容顶掉或拼接。再往深一层：利用 H2 注释、首部注入等 1.1 没有的语法把攻击文本嵌进对后端有意义的结构里。变体细节见 http2-attacks-test 模块。

## 出什么算成
同一连接上的后续请求（真实受害者流量）响应错位，或被你构造的走私请求污染。

## 假点（什么样不算）
中间层对降级做完整重编码和校验，矛盾体直接 400/断连；后端也是 H2 原生（没有翻译环节）；目标站根本没有 h2 入口。

## 为什么值钱（severity 依据）
主流站点都在上 H2，攻击面新且命中后果与传统走私同档（劫持/投毒/绕权），头部站点实测可打通，收高危到严重。
