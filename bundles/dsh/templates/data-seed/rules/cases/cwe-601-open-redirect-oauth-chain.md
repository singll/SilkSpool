# 案例：认证框架"登录后跳回"参数开放重定向、串走 OAuth 流程（中危，成链可至高）

> 来源: https://nvd.nist.gov/vuln/detail/CVE-2022-29214 · CWE: 601 · 首发年份: 2022
> 关联: rules/techniques/open-redirect-test.md · VC 卡: 无

## 模式（什么形状的目标会有这洞）
登录/认证框架的"登录后跳回"参数（callbackUrl / next / redirect / continue）校验太松：前缀匹配、只看 host 不看完整 URL、或对特定流程（判例是 OAuth 1 流程）漏了校验。这类库被成千上万站点复用，一处缺陷放大成一片站点。

## 打法（案例里实际打通的路径）
先打跳转参数本身：改成外域、@ 笔、反斜杠、编码变体，别看回包 200，看 Location 和浏览器最终落点（变体清单见 open-redirect-test 模块）。再成链：把带开放重定向的 URL 塞进钓鱼邮件/二维码当"官方登录链接"；更狠的是对着 OAuth 流程打——登录成功后流程会带着授权码或 token 跳向该参数指定的地址，跳转地址被劫持等于码被截胡。

## 出什么算成
官方域名下的 URL 把浏览器（或 OAuth 流程的授权码/token）送到了你控制的外域。

## 假点（什么样不算）
跳转参数只接受站内相对路径；外域跳转被确认页拦住、需要用户再点一次；仅能跳到同站其它页面——无外域落点不成立。

## 为什么值钱（severity 依据）
单看是中危，但它是钓鱼与 OAuth 票据窃取的标准前置件；认证库类缺陷影响所有下游接入站点，按供应链级处理。
