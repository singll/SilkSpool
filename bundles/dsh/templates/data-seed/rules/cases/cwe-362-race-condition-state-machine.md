# 案例：并发竞态击穿"只允许一次"的业务状态机（高危）

> 来源: https://portswigger.net/research/smashing-the-state-machine · CWE: 362 · 首发年份: 2023
> 关联: rules/techniques/race-condition-test.md · VC 卡: 无

## 模式（什么形状的目标会有这洞）
业务里有"同一操作只成功一次"的承诺：一次性优惠券、唯一兑换码、限一次提现、超发校验、验证码只可验一次。实现是"先查后写"两步走，中间没有原子锁。入口信号：领券/兑换/下单/绑卡类写口 + 文案或前端承诺唯一性。

## 打法（案例里实际打通的路径）
先低并发打一次，确认正常路径与回包形状。再用高并发工具同时打同一接口——原研究的关键是"单包攻击"：把几十个请求塞进同一个 TCP 包，消除网络抖动，把毫秒级竞态窗口变成稳定可复现。观察回包分布：出现两个以上"成功"即击穿。再打深一层：应用在多步流程间存在隐藏中间态（如邮箱换绑的窗口期），把多个端点编排成有顺序的并发组合去撞这些子状态。工具与编排见 race-condition-test 模块。

## 出什么算成
同一次唯一性操作在并发下**成功多次**（多张券、多次到账、多次兑换），或在中间态窗口读/写到不该暴露的数据。

## 假点（什么样不算）
后端有真实原子约束（唯一索引/分布式锁/事务），并发全失败只有一次成功；回包全 200 但只入账一次——那是幂等设计成功；慢工具偶发打出的"两次"无法复现。

## 为什么值钱（severity 依据）
直接等于资损或限额突破，原研究在头部站点批量验证过整类模式，赏金按业务资损上限发。
