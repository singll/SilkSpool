## 每次升级的记录方式

- 新建 `YYYY-MM-DD-dsh-<目标版本>-plan.md` 和 `YYYY-MM-DD-dsh-<目标版本>-record.md`，从 [TEMPLATE](TEMPLATE.md) 起草。
- 方案写清：现状、上游证据、确定需要适配的调用点、尚未验证项、依赖、验收和回滚。
- 记录先写预检；实施后追加开始/结束时间、实际版本、代码提交、产物与备份校验、测试结果、观察期和回滚情况。未执行的项目明确写“未执行”。
- 时间展示按 v5 约定使用北京时间 ISO（`+08:00`），引用上游发布时间时同时保留 UTC。
- 状态使用：`预检完成 / 方案待实施 / 实施中 / 观察中 / 已完成 / 已回滚 / 已被替代`。基础健康检查通过不等于升级完成。
- 文件迁移只调整导航和链接，不改写历史实施结论。新增相关设计也放在本目录，并由当次升级方案链接。
