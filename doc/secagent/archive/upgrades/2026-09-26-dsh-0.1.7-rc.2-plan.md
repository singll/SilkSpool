## 目标与范围

把生产 DSH 从 0.1.5-rc.2 升级到 0.1.7-rc.2，复用 0.1.5 的升级工具链（冻结 / 不变量 / 四根 `RENAME_EXCHANGE` / 回滚），只改五处适配：**版本参数 + Session V4 + Agent Preset + settings + 第三方插件**。

**包含**：

- P0-1 升级工具链「版本解放」（0.1.5/0.1.7 双版本参数化，旧版本判定保留）；
- P0-2 Session 日志 V3 → V4（采用上游 `@deepseek-ai/dsh-session-format-v3-to-v4`，不自维护 V0→V3 桥）；
- P0-3 Agent 预设机制替换（7 角色从 `.agent-presets/` 目录改为 `@deepseek-ai/dsh-agent-preset` bundle patch 行）；
- P0-4 settings.yaml → Profile 插件配置（`@deepseek-ai/dsh-settings`；旧文件仅导入一次，显式双 profile 落 patch）；
- P0-5 第三方插件升版（dsh-auth-gate 0.15.0 / dsh-bill 0.18.1 / dsh-model-failover 0.1.5）+ 计费补丁按 V4 投影重写；
- P0-6 部署链（先 `--dump-config` 校验后重启；「部分激活」态检测；自有插件不声明 `peerDependencies` 防误拦）；
- P0-1 表中的两个既存 bug（candidate 引用不存在文件、runtime-smoke override id 拼写）；
- U0–U4 全流程与验收矩阵、回滚。

**不包含（已定决策）**：

- 官方 `dsh-schedule` **完全不接入**（不启用 Web `schedule`/`time-context`/`ui-schedule`；自研 task 域定时为唯一调度通道）；
- 自研 interval 下限保持 300s（不向官方 60s 对齐）；
- 大数据 B4/S2 UI 改造顺延到升级后；
- 官方 DeepSeek 适配器迁移（D1）只做回归验证，不改走 `llm-pi-ai` 的 provider 结构。

## 回滚与恢复范围

| 触发 | 动作 |
|---|---|
| 备份/恢复预演失败、未知会话格式、关键插件不能加载 | 不进入生产切换 |
| Scope/actor/证据守卫回归，Session 历史损坏，核心 Web/worker 不可用 | 保持写入冻结，回滚整套发布并重新验收 |
| 模型请求、会话锁、调度收尾持续失败超出可用性预算 | 停止派单并按演练流程恢复；不靠无限重试拖过窗口 |
| 学习候选效果下降但平台兼容正常 | 只撤销对应知识/策略版本，不回滚 DSH |

- Session V4 迁移**不可逆**：回滚后旧版不可直接续写新格式会话；新会话作为隔离存档保留，冻结点恢复 + 业务事件对账由 `preserve_after_resume` 流程处理。
- 回滚不能只改 `package.json`；必须走 release 目录 `rollback/` 树 + `RENAME_EXCHANGE` 回切，并用冻结点恢复配置/领域库/证据的同一恢复点。
- 切流后新增数据不自动丢弃：先冻结并额外保存新状态，对账后按流程保留/重放，记录实际 RPO，不承诺零损失。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| Session V4 迁移不可逆、会话读取失败 | 全量副本预演 + 冻结点 + 回滚读回验证；采用上游迁移工具，不自行维护 V0→V3 桥 |
| Agent preset 迁移后 7 角色失效 | U1 逐角色断言 + U2 会话创建回归；旧 `.agent-presets/` 保留只读备份 |
| settings 一次性导入导致 headless 丢配置 | 显式双 profile 落 patch，不依赖导入；`--dump-config` 断言关键 row |
| 第三方插件不兼容 | 升版优先（peer 已核对：auth-gate/bill/failover 均满足 0.1.7）；dsh-bill 备选精确豁免 + 补丁重验 |
| 配置热更无回滚 → 半激活 | 先校验后重启；升级脚本显式检测/修复；U2 预演覆盖 |
| freeze 工具调度器摘要失配 | P2 适配：模块路径 `plugins/sec-domain-task/index.js`（当前 sha256 `6b21fb7e…`），`freeze-config-current.json` 期望摘要同步更新，U2 冻结预演验证 |
| `event_outbox` 大数据与升级冻结耦合 | B1 已实施（7 天/2 万行保留窗口，42 号补丁部署验收）；**冻结窗口内不做大批量删除**（§二.4 决策） |
