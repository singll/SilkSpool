## 真相源与维护规则

1. **术语**以 [领域语言](../../bundles/dsh/CONTEXT.md) 为准；**当前设计契约**以 v5/00–18 为准，冲突时以 00-conventions 为上位约束。
2. **已部署状态**需要运行态证据；PROGRESS 记录实施进度，升级 record 记录特定时点的检查、执行和回滚。历史数字不自动代表今天。
3. **升级文档统一放在 upgrades/**。每次使用日期与目标版本命名，方案与执行记录分开；共用 [记录模板](upgrades/TEMPLATE.md)。后续实施持续追加同一次升级的 record，不另建“最新升级”副本。
4. **archive/** 只保留历史架构、研究与旧状态快照。历史升级方案/报告已迁入 upgrades/；旧文中的版本判断、操作结论需结合当次实施复盘阅读。
5. 新方案未实施前不得覆盖 v5 定稿契约或勾选实施节点；进入实施时，先同步受影响域的契约、actor、事件和验收要求，再推进代码。
